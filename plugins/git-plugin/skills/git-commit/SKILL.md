根据git差异自动生成提交信息并完成提交操作。

## 流程

### Phase 1: 读取差异
- 使用 `git status` 查看当前工作区状态
- 使用 `git diff --staged` 查看已暂存的变更
- 使用 `git diff` 查看未暂存的变更
- 分析变更的文件类型和修改内容

### Phase 2: 生成提交信息
- 根据变更的文件类型（新增、修改、删除）生成分类
- 分析修改内容的关键特征（功能实现、bug修复、重构等）
- 生成符合约定式提交规范的提交信息格式：
  - feat: 新功能
  - fix: 修复bug
  - docs: 文档更新
  - style: 代码格式调整
  - refactor: 重构
  - test: 测试相关
  - chore: 构建工具或依赖更新

### Phase 3: 用户确认
- 向用户展示生成的提交信息
- 询问用户是否需要修改提交信息
- 如果用户需要修改，根据用户输入调整提交信息
- 获取用户最终确认

### Phase 4: 执行提交
- 如果用户确认提交，执行 `git commit -m "提交信息"`
- 如果存在未暂存的变更，询问用户是否先执行 `git add`
- 提交完成后显示提交结果和提交哈希

### Phase 5: 推送
- 询问用户是否是否需要推送
- 如果用户确认推送，执行 `git push`

## 注意事项
- 确保在git仓库中执行此skill
- 如果工作区没有变更，提示用户并结束流程
- 提交信息应简洁明了，准确描述变更内容
- 支持中英文提交信息
