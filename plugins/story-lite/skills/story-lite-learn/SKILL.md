# 定位

独立知识沉淀 skill，只负责识别、核实、去重并写入 library。

- 由 story-lite 调用时，沿用其 `<cwd>`、milestone 与 slug
- 用户直接点名时，默认使用当前对话；用户指定 story 时读取对应 `<slug_dir>`
- 未显式启用 story-lite 且用户未点名本 skill 时，不主动执行
- 所有确认直接在普通对话中完成，禁止调用 `AskQuestion` 或同类提问工具

# 提炼规则

- 使用中文
- 只保留可跨需求复用的模式、约束与搜索线索；需求特有逻辑不提取
- 采用“职责描述 + 入口函数名/类名/文件路径”的线索形式，不罗列完整 API 签名与参数清单
- 从对话和 story 文档收集候选知识，并检索相关代码核实；事实以代码为准
- 未实现方案、无法验证的推断和 library 已充分覆盖的内容不写入

# 流程

## 1. 收集与核实

1. 读取当前对话上下文。
2. 有 `<slug_dir>` 时读取原始需求、设计文档、总览和 review 报告。
3. 沿候选知识涉及的入口函数、类名和文件路径检索实际代码。

## 2. 对比 library

1. 检查 `<cwd>/.agent/library/overall.md`；不存在则视为空 library，不提前创建。
2. 存在时读取索引和相关子文档。
3. 将候选项分类：
   - **新增**：现有 library 未覆盖
   - **增强**：已有条目需要补充或纠正
   - **跳过**：已充分覆盖、不可复用或无法验证

没有新增或增强项时，直接说明“无可沉淀内容”并结束，不创建文件。

## 3. 预览与确认

直接在对话中逐项展示：

- 分类
- 目标文档
- 写入内容预览
- 代码核实线索

等待用户确认。用户提出调整时更新预览并再次确认；确认前不得写入 library。

## 4. 写入

- 优先追加或修订已有主题文档，保持现有风格
- 新主题创建 `<cwd>/.agent/library/<主题>.md`，并更新 `overall.md` 索引
- library 首次创建时生成最小索引：

```markdown
# Library

- [<主题>](<主题>.md)：<一句话范围>
```

- 写入后报告改动文件与新增/增强条目
