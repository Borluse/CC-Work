# 定位

独立知识沉淀 skill：识别、核实、去重并写入 library。入口是 `story-lite` 用户确认沉淀后的委托，或本 skill description 命中的显式调用；主技能只负责提示、触发与跟进，不内嵌提炼和写入规则。

出口：无新增或增强内容时直接结束，不创建文件；有候选时先预览并等待用户确认，确认后只写入用户选择的条目。

# 约定

路径与访问边界与 `story-lite` 约定对齐；冲突以主技能为准。下列为 learn 自用子集。

```
.agent/library/overall.md
.agent/library/<主题>.md
.agent/story/<slug>/原始需求.md
.agent/story/<slug>/总览.md
.agent/story/<slug>/index.yaml
.agent/story/<slug>/<milestone>/需求N_标题.md
.agent/story/<slug>/<milestone>/bug/BugN_标题.md
.agent/story/<slug>/<milestone>/review/需求N_标题_设计review.md
.agent/story/<slug>/<milestone>/review/需求N_标题_代码review.md
```

- `<cwd>`：当前工作目录；`.agent` 固定为 `<cwd>/.agent`。只直接访问该树，禁止扫描其他目录的 `.agent`。路径不存在时停止，并提醒在当前工作目录根部创建。
- 解析 story 时忽略 `.agent/story/quick/`。
- **触发**：由 `story-lite` 在用户确认沉淀后委托，或本 skill description 命中显式调用；其他场景不主动执行。主技能首次完成时的提示本身不是进入许可。
- **输入默认**：
  - 由 `story-lite` 委托且已有上下文时，沿用其 `<slug_dir>`。
  - 用户点名且未指定 story 时，默认仅使用当前对话。
  - 用户指定 story 时，在 `<cwd>/.agent/story/` 下解析对应 `<slug_dir>`，先读取主题根原始需求和 `index.yaml`，按主技能「总览读取策略」读取与候选知识相关的总览章节，再读取全部 milestone 工作目录中的设计文档、Bug 报告和 Review 报告（`quick/` 见上）。
- **确认**：全部在普通对话中完成，禁止调用 `AskQuestion` 或同类提问工具。

# 提炼规则

- 使用中文。
- 只保留可跨需求复用的模式、约束与搜索线索；需求特有逻辑不提取。
- **厚度**：每条 ≤1–2 句原则（方法论或指引）+ 一条核实线索；流程步骤、选项枚举、禁令原文、表格字段等执行细则留在 skill，不写入 library。
- 采用「职责描述 + 入口函数名/类名/文件路径」的线索形式，不罗列完整 API 签名与参数清单。
- 从对话和 story 文档收集候选知识，并按核实源核对；未实现方案、无法验证的推断不写入。
- **核实源**：业务行为以代码为准；Skill/约定类知识以对应 skill 或约定文档为准，并标明核实线索。

# 流程

## 1. 收集与核实

1. 读取当前对话上下文。
2. 若有 `<slug_dir>`：读取主题根的原始需求和 `index.yaml`，按主技能「总览读取策略」读取与候选知识相关的总览章节，再读取全部 milestone 工作目录中的设计文档、Bug 报告和 Review 报告。判断需求或 Bug 状态时以 yaml 对应条目为准；无该条目时回退总览「需求点 N」节、设计文档首部或 Bug 报告首部。只有用户明确要求完整盘点或证据存在冲突时，才整读总览。
3. 沿候选知识线索核实：业务查代码；Skill/约定查对应文档。

## 2. 对比 library

1. 检查 `<cwd>/.agent/library/overall.md`；不存在则视为空 library，不提前创建。
2. 存在时读取索引和相关子文档。
3. 将候选项分类：
   - **新增**：现有 library 未覆盖。
   - **增强**：已有条目需要补充或纠正。
   - **跳过**：已充分覆盖、不可复用或无法验证。
4. 若无新增且无增强（仅跳过或全空）：直接说明「无可沉淀内容」并结束，不创建文件。

## 3. 预览与确认

直接在普通对话中以表格逐项展示，编号以 `L` 开头连续编号（如 L1、L2）：

| 编号 | 分类 | 目标文档 | 写入内容预览 / 跳过理由 | 核实线索 |
|------|------|----------|-------------------------|----------|

1. 新增、增强须给出写入内容预览；跳过可只写精简理由。
2. 等待用户确认：可按编号选择（如「全部」「只写 L1,L3」「全拒」）；支持调整后再次确认。
3. 确认前不得写入 library；全部拒绝则不写入并结束。

## 4. 写入

1. 仅写入用户确认的新增与增强项。
2. 优先追加或修订已有主题文档，保持现有风格。
3. 新主题创建 `<cwd>/.agent/library/<主题>.md`，并更新 `overall.md` 索引。
4. library 首次创建时生成最小索引：

```markdown
# Library

- [<主题>](<主题>.md)：<一句话范围>
```

5. 写入后报告改动文件与新增/增强条目。
