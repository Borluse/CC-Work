# 模式：tdd

从 `原始需求.md` 出发，按需求点讨论方案，把方案写进 Wiki。这是持续维护，不是一次性导出。

写作格式见 [WRITING.md](WRITING.md)。提问规范与 `story-lite` 相同：每轮只问待处理前沿；每题给推荐；用户未答则按推荐确认并在落盘前复述。

## 与 export 的差别

| | export | tdd |
|--|--------|-----|
| 源 | 总览 / 设计文档 | 原始需求；用户给的方案口述 |
| 总览 | 多点无总览则停止 | 允许无总览、多需求点 |
| 产物 | 一次性 Wiki | 按需求点迭代的 Wiki |
| 内容 | 已有设计的摘要 | 概述 + mermaid + 方案描述 |

需求条目（背景/描述/验收）仍由 story-lite 写在 `原始需求.md`。本模式默认只维护 Wiki 方案层。

## 落盘目标

- 默认：`<slug_dir>/wiki/<标题>.md`
- 历史基线可另存 `<slug_dir>/<标题>TDD.md`（合入旧 Wiki 时）；不要把 L1 基线与当前方案混在同一节
- 不要改需求状态文档，除非用户要求把方案同步回原始需求

## 流程

### 1. 确认 Wiki

展示 slug。确认标题、路径、默认章节（简介 + 每个需求点一节功能说明）。源没有配置表则默认不要配置章。

已有目标 Wiki：续写，不要无确认覆盖。

### 2. 可选：合入基线

用户要合入历史 Wiki/TDD 时：

1. 复制到当前 slug，按用户命名
2. 文首注明来源与「基线 / 尚未写入当前方案」
3. mermaid 标签补双引号（见 WRITING.md）
4. 不自动把基线章节当成当前需求点方案

### 3. 按需求点讨论

一次只推进用户指定的需求点。顺序：

1. 读原始需求该点 + Wiki 已有对应节
2. 用户给出方案：整理为「概述 + mermaid + 方案描述」草稿
3. 影响行为的未决项用 Q1… 访谈；推荐项用户未答则按推荐落盘并复述
4. 确认后写入该需求点所在节
5. 用户切换需求点或改结构时再动其他节

默认写 **方案描述**，不写 **难点**。用户明确要求难点时再加。

### 4. 维护

已有 Wiki 上的局部改写也走本模式，例如把 TDD/基线某章挪进 Wiki 对应需求点（源文件删除该章，文首改指向 Wiki）。

写完提醒用户打开确认。
