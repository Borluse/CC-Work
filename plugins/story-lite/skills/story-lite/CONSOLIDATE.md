# 整合与总结

前置：已完成主技能定位，并已读取主技能的约定、状态规则与模板门禁。

入口：用户要求整合、生成总览、里程碑收尾或总结。

出口：整合写入需用户确认后结束；总结只输出结果、不写文件。

## 1. 范围

默认当前正式需求 slug。若用户说「里程碑收尾」：处理所有含当前 `<ms_dir>` 的正式 slug（排除 `.agent/story/quick/`）。各 slug 独立整合。不另建里程碑总览。

## 2. 整合

1. 若存在总览：读主题根总览、`index.yaml`、全部 `<ms_dir>` 的设计文档与代码，生成 `总览.md` 刷新草案。
2. 若为无总览单点：读原始需求、`index.yaml`、设计文档与代码，生成设计文档刷新草案。
3. 同时读取相关 Bug 报告作为修正线索。以代码为准并标注差异。去重。不把修复历史直接合入当前设计。不写代码中不存在的功能。保留关键决策。对话输出差异报告。
4. 用户确认后写入前：对总览清单或无总览单点中尚无 `items` 的需求点，按总览或设计文档补这一条（`status`、`file`、Review 路径从现有状态行迁入，`keywords` 按约定从设计抽出或不写），已有账本条目的 `status` 不改。随后把整合正文按当前总览模板写入；无总览单点按当前需求点模板写入，并按约定处理该条 `keywords`。

## 3. 总结

1. 读 `index.yaml`；存在总览时再读总览、设计、Bug、Review；无总览单点再读原始需求、设计、Bug、Review。
2. 完成项、进行中、阻塞以 `items[].status` 分组，已关闭 Bug 以 `bugs[].status` 分组；无对应条目时回退总览、设计文档或 Bug 报告。
3. 只输出结果，不写文件。

## 4. 里程碑收尾

1. 全部正式 slug 处理完后输出里程碑摘要。
2. 用户确认即结束。不改 `milestones.yaml`，除非用户要求切换 `current`。
3. Quick 不进入本模式；转正式需求时转 `QUICK.md`，重新执行定位。
