# 整合与总结

前置：已完成主技能定位，并已读取主技能的约定、状态规则与模板门禁。

入口：用户要求整合、生成总览、里程碑收尾或总结。

出口：整合写入需用户确认后结束；总结只输出结果、不写文件。

## 1. 范围

默认当前正式需求 slug。若用户说「里程碑收尾」：处理所有含当前 `<ms_dir>` 的正式 slug（排除 `.agent/story/quick/`）。各 slug 独立整合。不另建里程碑总览。

## 2. 整合

1. 若存在总览：先读 `index.yaml`，再按主技能「总览读取策略」读取总览中与当前整合范围相关的目标、约束、系统盘点、跨需求依赖和未闭合问题章节；随后读取全部 `<ms_dir>` 的设计文档、相关 Bug / Review 与代码，生成 `总览.md` 刷新草案。历史变更记录仅在核对决策演进或处理冲突时读取；用户明确要求完整盘点时才整读总览。
2. 若为无总览单点：读原始需求、`index.yaml`、设计文档与代码，生成设计文档刷新草案。
3. 同时读取相关 Bug 报告作为修正线索。以代码为准并标注差异。去重。不把修复历史直接合入当前设计。不写代码中不存在的功能。保留关键决策。对话输出差异报告。
4. 用户确认后写入前：对总览清单或无总览单点中尚无 `items` 的需求点，按总览或设计文档补这一条（`status`、`file`、Review 路径从现有状态行迁入，`keywords` 按约定从设计抽出或不写），已有账本条目的 `status` 不改。随后按当前总览模板写入：只保留当前跨需求摘要、简明需求清单、有效约束、跨需求依赖和未闭合问题；需求点详细设计、实现核验和修复过程留在各自文档中，已有章节就地更新，不追加重复章节或重复依赖图。无总览单点按当前需求点模板写入，并按约定处理该条 `keywords`。

## 3. 总结

1. 读 `index.yaml`；存在总览时按主技能「总览读取策略」读取与摘要范围相关的总览章节，再读设计、Bug 和 Review；无总览单点再读原始需求、设计、Bug 和 Review。只有用户明确要求完整盘点，或账本与相关文档无法确定目标状态、依赖或风险时，才整读总览。
2. 完成项、进行中、阻塞以 `items[].status` 分组，已关闭 Bug 以 `bugs[].status` 分组；无对应条目时回退总览、设计文档或 Bug 报告。
3. 只输出结果，不写文件。

## 4. 里程碑收尾

1. 全部正式 slug 处理完后输出里程碑摘要。
2. 用户确认即结束。不改 `milestones.yaml`，除非用户要求切换 `current`。
3. Quick 不进入本模式；转正式需求时转 `QUICK.md`，重新执行定位。
