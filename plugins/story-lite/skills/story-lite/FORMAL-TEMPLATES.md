# 正式需求模板

## 原始需求

```markdown
# 原始需求：<slug 描述>
- <YYYY-MM-DD HH:mm>：初始创建
（后续变更记录继续追加在标题下）
## 1. 需求背景
## 2. 需求描述
## 3. 验收标准
```

## 总览

`总览.md` 只维护跨需求的当前摘要；状态、编号、里程碑、文档路径和 Review 路径以 `index.yaml` 为准。需求点章节从 `## 5` 起连续编号，每个章节只写该点的简短摘要或影响跨需求的关键决策；详细设计、实现核验和修复过程留在对应需求点、Bug、Review 文档中。已有章节就地更新，不追加重复章节或重复依赖图；变更记录只记录总览聚合变更。

```markdown
# 总览：<slug 描述>
## 1. 整体目标与技术约束
## 2. 现有系统盘点
| 系统/模块 | 位置 | 当前职责与关系 |
|-----------|------|----------------|
| … | … | 复用/扩展/只参考；当前职责 |
## 3. 需求点清单
| 编号 | 需求点 | 里程碑 | 当前摘要 | 依赖 |
|------|--------|--------|----------|------|
| 1 | … | … | … | - |
## 4. 跨需求依赖
（使用 mermaid flowchart，只保留跨需求依赖；必要时列出实施顺序）
## 5. 需求点 N：<标题>
- 摘要：…
- 关键决策：…（仅影响跨需求契约、依赖、系统关系或风险的内容）
## 6. 变更记录
- <YYYY-MM-DD HH:mm>：总览聚合变更
```

## 需求点

```markdown
# 需求N：<标题>
- 关键决策：…（仅既有无总览单点需求）
## 1. 需求简介
一句话。
## 2. 功能说明
策划目标 + 技术行为。
## 3. 设计细节
设计要点（可配 mermaid/伪代码）。
## 4. 变更记录
- <YYYY-MM-DD HH:mm>：初始创建/修改
```
