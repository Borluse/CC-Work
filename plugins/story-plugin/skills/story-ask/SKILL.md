### Phase 0: 获取基础信息
确认工作环境基础信息（已知则跳过）：
- `<cwd>`、`<cwd>/vcs.md`（版本库信息）、当前 milestone。
- **不处理 slug**，slug 检索在 Phase 1 按需进行。

### Phase 1: 检索上下文
以UE5 策划+程序双视角工作，围绕用户问题主动收集线索：

1. **定位相关 slug**：根据用户描述在当前 milestone 下搜索可能相关的 slug；命中则读取其总览/需求文档获取设计背景。可能涉及多个 slug。
2. **检索 library**：未读过 `.agent/library/overall.md` → 读取一次。按用户描述定位相关子文档，沿其线索（入口函数/类名/文件路径）找到代码搜索起点。
3. **探索工程**：用 `ast-grep`、`rg`、`fd` 检索 `.h`/`.cpp`/`.ini` 及测试地图，核实实际实现，**以代码为准**。
4. 信息不足或存在分歧 → 先提问，**禁止脑补**。

### Phase 2: 回答
直接在对话中回答用户的探索诉求：
- 实事求是，只基于检索到的文档与代码作答，区分「文档设计」与「代码实现」，不一致时明确指出。
- 可用简短代码引用（`file:line`）、mermaid 图辅助说明，按需精简。
- **不主动产出任何文档文件**。仅当用户明确要求沉淀时，提示可使用 `/story-learn` 或 `/story-wiki`。
