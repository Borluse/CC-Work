将某个 story 目录下的多份需求文档，根据实际代码合并为一份总览文档。

## ⚠️ 强制要求：使用 subagent 执行

**你必须使用 Agent tool 来 spawn `story:ue5-expert` subagent 执行合并任务。**
**严禁在主会话中直接执行代码阅读或文档编写。**

### 执行步骤

1. 主会话完成 Phase 1（定位目标、确认范围）
2. 调用 Agent tool，参数如下：
   - `subagent_type`: `story:ue5-expert`
   - `prompt`: 包含以下全部内容的完整指令：
     - 需求文档列表及路径
     - 核心代码文件列表（从 memory 或用户提供）
     - 下方「合并规则」章节的全部内容
3. 等待 subagent 返回结果后，将文档路径和关键差异摘要呈现给用户

---

## 合并规则（传递给 subagent）

- 与项目有关的设计，代码，规则等，加载 `.agent/library/overall.md` 获取知识
- 当涉及 C++ 代码，加载 `.agent/library/common/ue5-cpp-rule.md` 获取规范

### Phase 1 定位目标

1. 扫描 `.agent/story/` 列出所有 story 目录
2. 让用户选择要整理的目录（如用户已在参数中指明则跳过）
3. 扫描选中目录下所有需求文档（`需求*_*.md`，排除 `Review/` 子目录）
4. 列出文档清单，向用户确认范围
5. 确认核心代码文件列表：
   - 优先从 memory 文件中获取（如有）
   - 否则请用户提供
   - 或从需求文档的「涉及文件」章节汇总

**必须**得到用户的明确确认，才能进入下一步。

### Phase 2 合并整理

subagent 执行以下步骤：

#### Step 1：读取所有需求文档

读取选中的全部需求文档，提取每份文档的核心内容。

#### Step 2：读取实际代码

读取核心代码文件的 .h 和 .cpp，重点关注：
- 所有 CVar 定义及当前默认值
- public/protected 接口签名
- 关键函数的实际实现逻辑
- 配置数据类的属性定义

#### Step 3：对照合并

按总览文档模板（`./references/consolidate-template.md`）结构输出，遵循以下原则：

- **以代码为准**：文档描述与代码不一致时，以代码实际实现为准
- **去除历史痕迹**：不保留"修改前/修改后"对比，只描述当前状态
- **删除未实现内容**：代码中不存在的功能不出现在文档中
- **去重合并**：多份文档中重复描述的内容只保留一份
- **保留设计决策**：重要的"为什么这样做"的决策说明要保留
- **标注差异**：发现文档与代码不一致时，记录到差异清单中

#### Step 4：输出差异报告

合并完成后，输出一份差异报告，列出所有文档描述与代码实际不一致的地方，供用户确认。

### Phase 3 写入文档

- 文件命名：`<story目录>/总览_<系统名>.md`
- 系统名从需求文档标题中提炼（如多份需求都围绕"推挤/穿透"，则系统名为"怪物穿透推挤系统"）
- 如果已存在同名总览文档，询问用户是覆盖还是新建

文档写完后：
- 提醒用户打开文件确认
- 展示差异报告摘要
- 提示用户：可进入 Review 阶段或进一步修正
