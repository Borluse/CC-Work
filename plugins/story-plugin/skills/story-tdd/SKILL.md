- **前置**：加载 `${CLAUDE_SKILL_DIR}/../common/basic.md`（同会话已读则跳过）。

# 1. 统一文档与图示规范
- **极简前置**：1~3 句说清核心机制（触发条件 → 状态转换 → 结果），不堆砌列表。
- **强制图示规则**：只用简洁 `mermaid flowchart`（判定节点用短中文，严禁变量/函数名溢出）。**禁止**时序图、类图等复杂程序图。
- **伪代码边界**：仅极其复杂业务逻辑时用**无行号纯伪代码**概括方向，严禁真实实现细节和具体接口设计。
- **严禁主观评价**：不写"好处是..."。实事求是，不推测不补充需求。

# 2. 执行阶段

### Phase 1: 需求分类与自动化盘点
1. 按 `basic.md`「Slug 检索流程」确认 slug，读取 `原始需求.md`（无则提示用户提供）。
2. 用 `fd`/`rg` 探索代码库，找出相关已有系统/模块/基类。
3. **分流判定**：**[A. 怪物类需求]** 还是 **[B. 通用系统需求]**。

### Phase 2: 一站式拆分与整体对齐（核心卡点）
> AI 整体理解与拆分同步进行，拒绝多次打断。
按"复用优先、独立交付、粒度适中"原则完成拆分，一次性输出：
1. **大需求整体目标与技术约束**、现有系统盘点报告（明确复用/扩展/继承关系）。
2. **需求点清单表格**（名称、一句话目标、功能范围、方案思路、预估复杂度及风险）。
3. **实施依赖图**（`mermaid graph` 拓扑排序）。
4. **拟采用的文档模板章节结构**（由 Phase 1 分流结果决定）。

⚠️ **必须停下等待用户确认。**

### Phase 3: 格式化输出 TDD 文档
用户确认后，按分流类型套用结构输出 TDD 文档：

#### [分支 A: 怪物类 TDD 结构]
- **1. 怪物概述**（核心玩法、技能清单及背景简述）。
- **2. 制作方案规划**（蓝图/AI/动画状态机等技术点盘点，不展开细节）。
- **3. 技能制作拆解**（标准技能合并描述。每个技能：简介、释放条件与默认CD、流程图示、配置方向、资源需求与性能考量）。

#### [分支 B: 通用系统 TDD 结构]
- **1. 需求简介**（核心机制总览流程图）。
- **2. 现有系统盘点**（类名、位置、关系表格：扩展/复用/继承）。
- **3~N. 各需求点技术方案**（设计意图、配置项表格[类型/默认值/说明]、流程图、关键约束 Callout）。
- **最后一章. 实施顺序与依赖**（依赖图、实施顺序表）。
- **变更记录**（初稿说明）。
