# 使用约定（所有 story-* skill 共享）

任意 `story-*` skill 在执行第一步动作前，**必须**加载本文件（同会话已读则跳过）。子 skill 在 SKILL.md 顶部统一使用：

> **前置**：加载 `${CLAUDE_SKILL_DIR}/../common/basic.md`（同会话已读则跳过）。

涉及代码规范或设计原则的 skill 可附加加载 `${CLAUDE_SKILL_DIR}/../common/gamedesign.md`。

## 运行时条件加载（加载本文件后判断执行）

当本文件被加载后，**严格按以下顺序**判断并执行，**禁止跳步或乱序**：

### Step 0（阻断性前置，必须最先执行）
1. 使用 Read 工具读取**相对路径** `.agent/milestones.yaml`。
   - ⚠️ **禁止**拼接绝对路径、禁止 cd 到其他目录、禁止猜测路径。直接读 `.agent/milestones.yaml`。
   - 若文件不存在，**报错停止**，提示用户执行 `/story-milestone` 创建。
2. 读取成功后，向用户输出：`📍 当前 milestone: <current>`。
3. **只有完成上述两步后**，才可执行任何 slug 检索或文件操作。

### Step 1（条件加载）
| 条件 | 动作 |
|------|------|
| 任务涉及 C++ 代码（设计、实现、Review） | **必须**加载工程目录下 `.agent/library/common/ue5-cpp-rule.md` |
| 工程目录下存在 `.agent/library/overall.md` | **必须**加载该文件作为项目全局上下文 |

以上加载遵循「同会话已读则跳过」原则。


# 方案，需求设计规则
当与用户讨论方案或者设计细节时，请就这个方案或设计的每一个细节对我进行持续的深度追问，直到我们达成完全一致的理解。请遍历设计树的每一个分支，逐一梳理并解决各个决策之间的依赖关系。针对每一个问题，请附上你推荐的解答或建议。如果某个问题可以通过探索代码库来得出答案，请主动使用 ast-grep、rg 或 fd 等命令行工具直接去探索代码库检索相关逻辑，提取信息后再做决策。
提问题时，禁止使用`askuserquestion`工具 。

## 提问与选项编号规范（强制）
- 将问题做一个分类
- 问题的结构：
  - Q1.(Q+数字) 问题标题
  - 原因解释（原因/影响面/涉及面等）
  - A/B/C 可选项，
  - 推荐选项以及为什么
  - 分隔符

# 目录简介

文档都在**当前工作目录**的 `.agent`下
忽略文件：无需访问 wiki 和 archive 目录。
核心流转：读取原始需求 -> 讨论输出TDD -> 拆解为多个需求*_.md -> 结束后合并为总览.md。

例如当前的工作目录为 D:\Work
所有的文档获取和上下文加载，均默认以当前全局配置根目录（即 .agent 所在的工作目录）为基准构建相对路径。

目录结构如下：
```
D:\Work\.agent
├── milestones.yaml
├── library/
└── story/
    ├── 切片1/                       ← milestone 目录
    │   ├── 2026-5-20_怪物推挤/      ← slug 目录
    │   │   ├── wiki/
    │   │   ├── archive/
    │   │   ├── Review/
    │   │   │   └── 需求1_代码Review.md
    │   │   ├── TDD_怪物推挤.md
    │   │   ├── 需求1_需求描述.md
    │   │   ├── 总览.md
    │   │   └── 原始需求.md
    │   └── 临时快速需求/
    └── MS10/                        ← 另一个 milestone
        └── 2026-4-15_基础战斗/
```

## Milestone 配置（`.agent/milestones.yaml`）

```yaml
current: 切片1
milestones:
  切片1:
    created: 2026-05-20
  MS10:
    created: 2026-04-15
```

- **强制前置**：此文件必须存在，不存在则报错停止。
- `current` 指向当前活跃的 milestone，所有 slug 操作默认在该 milestone 目录下执行。

### Slug 检索流程（所有 story-* skill 共享）

定位、验证、匹配 Slug 或 Story 目录时，**必须**按以下流程执行，严禁绕过：

1. **确定目标 milestone**：
   - 若用户输入中提及了已知的 milestone 名称（匹配 YAML 中的条目），则在该 milestone 目录下操作。
   - 若用户提及的 milestone 名称不存在于 YAML，**直接报错停止**。
   - 若用户未指定 milestone，使用 YAML 的 `current` 值。
2. **检索命令模板（强制，禁止修改）**：在当前工作目录（cwd）执行，**必须使用相对路径**：
   ```bash
   fd . .agent/story/<milestone>/ -t d --max-depth 1
   ```
   - ⚠️ **严禁**将 `.agent/story/` 替换为绝对路径或其他变体（如 `.story`、`story/` 等）。
   - 再用 `rg -i "<关键词>"` 在结果中过滤。
3. **路径红线**：
   - **一切路径操作必须基于 cwd 的相对路径**。禁止拼接绝对路径前缀（如 `D:/CFH/`）。
   - 仅以 `.agent/story/<milestone>/` 作为基准相对路径。
   - **严禁**在 `D:\` 等整盘、引擎目录、plugin 仓库（如 `D:/ClaudeCode/CC-Work`）下盲搜。
   - 不确定 cwd 时先 `pwd`，**禁止**靠猜路径试探。
4. **兜底**：若 `.agent/story/<milestone>/` 不存在，直接告知用户并停止，不要扩大搜索范围。
5. **Slug 命中后**：进入子流程前，**至少**读取该 slug 目录下的 `原始需求.md` 与 `总览.md`（若存在），并列出已有需求点 / Review 文件，作为后续操作的上下文基线。
 
## 文档规则
- 需求标号总是为自增，例如，`需求1`, `需求2`
- 一个slug下总是只有一个`总览.md`

## Slug命名规则
- 提炼 ≤5 词中文短语作为目录名（如 `怪物推挤`），向用户确认。
- 目录格式为 `日期_需求slug`，日期为生成该slug的时间，例如 `2026-4-30_怪物推挤`
- Slug 目录创建在 `.agent/story/<current milestone>/` 下。
- 在开启新任务或缺失 slug 上下文时，必须向用户确认当前的 slug 名称。


# 文档先行规则
任何实质性的变更（包括但不限于逻辑分支、数据结构、接口签名、UE元数据等），必须先更新对应的需求文档及总览，再修改源代码。
修改后在文档末尾追加：<YYYY-MM-DD>：[类型] 变更简述（严禁大段记录）。
