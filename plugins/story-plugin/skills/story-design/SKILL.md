### Phase 0: 初始化环境
- @../common/gamedesign.md
先调用 `/story-init`（**create-slug 模式**）完成工作环境初始化。
- **门禁**：`/story-init` 完成后方可继续，若已执行则跳过。

### Phase 1: 需求理解与方案设计
以UE5 策划视角工作
1. 读取 `Tdd` 和 `原始需求`（如有），来补充上下文
2. 梳理核心功能边界、测试用例，**不涉及具体代码实现细节**。
3. 找出未决设计分歧或与前置文档冲突处。
4. **打断点**：输出设计梳理结果 + 需澄清问题。**等待用户确认后再进入下一步。**
5. 不扫描二进制资产。


### Phase 2: 输出标准化设计文档
用户确认后，按精简模板生成`需求N_需求标题.md`，并同步更新 TDD（若有变更）。


**文档模板结构**：
- **1. 需求简介**：一句话核心描述。
- **2. 功能说明**：融合策划目标与技术行为。
  - **2.1 边界条件**：表格列出特殊情况/异常处理。
- **3. 配置项**：DataAsset 可配置参数（文件位置、类型、默认值）。
- **4. 接口设计**：核心接口 C++ 声明。每个接口**必须包含注释**。蓝图接口用 `> [!tip]` 说明调用方式。
- **5. 实现方案**：
  - **5.1 涉及文件**：表格列出相关类/模块。
  - **5.2 类图结构**：`<mermaid classDiagram>` 新增/修改类及关系。
  - **5.3 功能模块**：拆分子章节，简述逻辑/目标/角色。callout 标注风险。
    - **5.3.X.1 伪代码**：接口/函数单独代码块，前置一句话说明职责。
    - **5.3.X.2 图示**：优先流程图。模块多可用时序图。简单功能跳过。关于行为树的则按照行为树的方式绘制，蓝图按照蓝图
- **6. 调试接口 / 7. 蓝图使用说明 / 8. 待确认事项**：不涉及则整章跳过。
- **9. 变更记录**： `- <YYYY-MM-DD HH:mm>：初始创建/修改`。 

如果用户提出意见，修改设计并等待用户确认。
在确认后进入到phase 3
