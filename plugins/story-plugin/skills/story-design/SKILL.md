### Phase 0: 初始化环境
- @../common/gamedesign.md
先调用 `/story-init`（**create-slug 模式**）完成工作环境初始化。
- **门禁**：`/story-init` 完成后方可继续，若已执行则跳过。

### Phase 1: 需求理解与方案设计
以UE5 策划视角工作
1. 读取 `Tdd` 和 `原始需求`（如有），来补充上下文
2. 梳理核心功能边界、测试用例，**不涉及具体代码实现细节**。
3. 找出未决设计分歧或与前置文档冲突处。
4. **打断点**：输出设计梳理结果 + 需澄清问题。**等待用户确认后再进入下一步。**
5. 不扫描二进制资产。


### Phase 2: 输出标准化设计文档
用户确认后，按精简模板生成`需求N_需求标题.md`，并同步更新 TDD（若有变更）。


**文档模板结构**：
- **需求简介**：一句话核心描述。
- **功能说明**：融合策划目标与技术行为。
- <中间补充必要的设计细节，目的是让用户可以了解实现方案。规则:需要图文并茂，图使用mermaid。代码部分需要用伪代码表达。>
- **变更记录**： `- <YYYY-MM-DD HH:mm>：初始创建/修改`。 

如果用户提出意见，修改设计并等待用户确认。
在确认后进入到phase 3

提示用户 "可进入代码实现阶段"。
