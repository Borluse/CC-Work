从设计文档或当前对话上下文中提炼项目级可复用模式，写入 `.agent/library/` 对应文档。

支持两种输入模式：
- **Story 模式**：从 `.agent/story/` 下的设计文档提炼
- **上下文模式**：从当前对话上下文中的技术讨论/代码/结论提炼

> [!warning] 只读约束
> **严禁**修改 `.agent/story/` 下的需求文档和项目源代码，仅允许在 `.agent/library/` 目录下创建或更新文档。

---

## 全局规则

- 文档用**中文**撰写
- 遵循 library 的精简原则：线索导向，不罗列参数/属性/方法（参考 `library/common/doc-rule.md`）
- 提炼的是**可复用的项目方法论**，不是需求本身的功能描述
- 所有操作在当前工作目录下执行，不用绝对路径

---

## Phase 1：确定输入来源

判断输入模式：
- 如果用户提供了上下文内容（如技术讨论、代码片段、设计结论等），进入 **上下文模式**
- 如果用户没有提供上下文，或明确指定从 story 提炼，进入 **Story 模式**
- 如果无法判断，询问用户

### Story 模式
1. 扫描 `.agent/story/` 下所有需求文档（`需求*_*.md`，排除 `*_Review.md`）
2. 列出文档清单，让用户选择要提炼的文档（可多选）
3. 读取选中的设计文档

### 上下文模式
1. 从当前对话上下文中提取技术信息（设计决策、代码模式、踩坑经验等）
2. 向用户确认提取到的关键信息是否完整

### 两种模式共同步骤
- 读取 `.agent/library/overall.md`，了解 library 当前结构和已有内容

**必须**得到用户的明确确认，才能进入下一步。

---

## Phase 2：提炼方法论

从输入内容中提取可复用模式，分以下维度分析：

### 提取维度

- **架构模式**：如 Component+ConfigData 分离、委托扩展机制、DataAsset 配置驱动等
- **设计决策**：如 CVar vs 配置项的选择、Hit vs Overlap 的取舍、同步 vs 异步方案等
- **边界处理**：共性的边界条件处理方式（如空指针防御、无效输入降级等）
- **可复用代码模式**：如方向计算、安全位置预测、定时器管理等惯用写法

### 过滤规则

- **只提炼可跨需求复用的模式**，需求特有的逻辑不提取
- 与 library 现有内容对比，识别出：
  - **新增**：library 中完全没有的模式
  - **增强**：library 中已有但可补充细节/新场景的模式
  - **跳过**：library 中已充分覆盖的内容

### 输出格式

向用户展示提炼结果清单：

```
## 提炼结果

### 新增
1. [模式名称] → 目标文档路径
   - 一句话描述

### 增强
1. [模式名称] → 目标文档路径
   - 现有内容摘要 + 新增内容摘要

### 跳过（已覆盖）
1. [模式名称] - 原因
```

**必须**得到用户的明确确认，才能进入下一步。

---

## Phase 3：写入 library

根据用户确认的提炼结果，执行写入：

1. **定位目标文档**：根据 `overall.md` 中的索引，找到对应的 library 文档
   - 如果是已有文档的增强，直接追加/合并到对应章节
   - 如果是新增模式且无合适文档，创建新文档并更新 `overall.md` 索引
2. **写入内容**：
   - 遵循精简原则（线索导向，不罗列参数）
   - **必须**尽量精简 token 数
   - 保持与现有文档风格一致
3. **更新索引**：如有新文档，在 `overall.md` 或相关总览文档中添加索引条目
4. **输出更新摘要**：
   - 列出所有更新的文件路径
   - 提醒用户打开文件确认内容
