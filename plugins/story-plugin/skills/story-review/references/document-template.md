## Review 报告模板

设计 Review 和代码 Review 共用以下结构，差异部分已标注：

```markdown
# 需求<N> [设计/代码] Review 报告

| 字段 | 内容 |
|------|------|
| 关联需求 | `需求<N>_<功能名>.md` |
| Review 日期 | <YYYY-MM-DD HH:mm> |
| 涉及文件 | <文件列表>（仅代码 Review） |

## 总体评价

<一段总结，说明整体质量和主要风险>

## 问题清单

问题表格列：设计 Review 用 `# | 章节 | 问题描述 | 建议修改`；代码 Review 用 `# | 文件 | 行号 | 问题描述 | 建议修改`。

### 🔴 必须修改
### 🟡 建议修改
### 🟢 可选优化

## 优点记录

<值得推广的良好实践/设计决策>

## 结论

- [ ] 通过（设计 Review：可进入实现阶段；代码 Review：可以提交）
- [ ] 有必须修改项，修改后重新 Review
```
