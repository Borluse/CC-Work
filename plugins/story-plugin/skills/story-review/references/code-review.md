**Step B1 深度代码 Review** — 读取需求文档，提取「涉及文件」列表，使用 `ue5-reviewer` agent 执行深度 Review。维度：
- 需求文档与代码实现的一致性
- 代码健壮性与性能
- 是否符合项目规范
- 跨平台兼容性（DS 服务器、手机、编辑器）
- 可简化或重构的部分

**Step B2 输出报告** — 在需求文档同目录下生成 `需求<N>_代码Review.md`，按下方报告模板输出。

**Step B3 等待审批** — 用户确认后进入 B4。

**Step B4 修改代码** — 仅处理用户确认的修改项。**文档先行原则**：涉及接口、结构体、逻辑流程等设计层面调整时，先编辑需求文档 → 追加变更记录 `[代码Review]` → 再修改源代码。

**Step B5 完成** — 提醒用户查看修改结果，如有未处理项可再次使用 `/story-review`。
