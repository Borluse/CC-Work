## 需求1：设计阶段提问规范

### 需求背景

story-lite 插件（v0.1.0）当前 SKILL.md 中与提问相关的规范只有一句：「每个问题附标题、原因、可选项、推荐项；禁止脑补，可查代码的用 ast-grep/rg/fd 查证」。缺少对「设计阶段如何提问」的完整约束，实际使用中容易一次性输出方案、替用户做决定、未确认细节就落文档。

### 需求描述

1. 在 `plugins/story-lite/skills/story-lite/SKILL.md` 中新增独立章节「设计阶段提问规范」，自包含地固化以下规则：
   - 与用户讨论方案/设计细节时，对每个细节持续深度追问，直到达成完全一致理解；
   - 提问采用批量方式：一次性提出当前设计树全部未决问题（Q 编号 + 四要素），不逐个提问；用户一次性答复，答复引出新问题时下一轮再批量提出，迭代直至完全一致；
   - 遍历设计树每个分支，逐一梳理解决各决策依赖关系；
   - 每个问题附推荐解答/建议；
   - 若问题可通过探索代码库得答案，主动用 ast-grep、rg、fd 检索相关逻辑后再做决策；
   - 提问时禁止使用 `askuserquestion` 工具；
   - 提问需包含：标题、原因、可选项、推荐选项及其原因；
   - 所有出现疑问/不确定的地方均按此方式提问，不预设用户答案、禁止脑补；
   - 细节全部确认前不落任何文档，全部确认后一次性落盘，再走文档确认循环。
2. 提问编号采用 Q 递增编号（Q1、Q2…），四要素必填，不强制分类与分隔符。
3. Design 模式流程改写：先按提问规范对话澄清，全部细节确认后再落盘设计文档。
4. 版本与文档同步：`.claude-plugin/plugin.json` → 0.1.1；`.codex-plugin/plugin.json` → 0.1.1+codex.20260802000627；根 README 版本号与 story-lite 描述同步更新。

### 验收标准

- SKILL.md 包含上述章节，Design 模式流程体现「先提问确认、后落盘」；
- 提问格式符合 Q 编号 + 四要素；
- 插件版本号与 README 已同步；
- 不修改 story-plugin 等其他插件内容。

## 需求2：插件结构优化

### 需求背景

story-lite 当前为单文件结构（SKILL.md 163 行 + 双 manifest），整体自包含且内部规则闭环，但结构上有 4 处可优化：`## Milestone 配置` 语义上嵌套在「设计阶段提问规范」章节内；工作流程缺少「触发词 → 模式」路由表；六类文档（原始需求、quick、TDD、设计文档、总览、review 报告）只有设计文档与 milestones.yaml 有显式模板；总览的「状态」字段无枚举、取值自由。以上均不涉及工作流步骤或效果变化。

### 需求描述

1. **章节归类**：SKILL.md 重排为「定位 → 文档结构与约定（含 Milestone 配置）→ 设计阶段提问规范 → 工作流程」，将 Milestone 配置从「设计阶段提问规范」下移出；在「约定」中新增总览状态枚举。
2. **触发词路由表**：工作流程开头新增「模式路由」小节，映射用户触发词到 9 个模式。
3. **模板补齐（全部内联）**：原始需求、quick、TDD、设计文档、总览、review 报告各补显式模板，内容与现有文字规则一致，不引入新规则。
4. **状态枚举**：约定中定义「待设计 / 设计中 / 已确认 / 实现中 / 已完成 / 已Review / 阻塞」，需求1 在总览中的状态表述归一为枚举值。

### 验收标准

- SKILL.md 章节顺序为「定位 → 文档结构与约定 → 提问规范 → 工作流程」，Milestone 配置不再嵌套在提问规范下；
- 工作流程开头有「触发词 → 模式」路由表；
- 六类模板全部内联且与现有规则一致；
- 总览状态使用枚举值；
- 工作流 9 个模式步骤、quick/正式规则、review 流程、提问规范内容保持不变；
- 不修改 story-plugin 等其他插件内容。
